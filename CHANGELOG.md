# Changelog

All notable changes to InstallScope are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Guided PAF projects
- Added reviewed source staging with explicit file mappings, original-file preservation, source/destination separation, link/name/collision checks, cancellable streaming copies and SHA-256 verification against reviewed contents. New output never overwrites an existing folder; failures keep labeled partial output. A project snapshot and preparation report accompany the new package.
- Added bounded static-PNG icon import, an exact 128-pixel preview, documented PNG variants and ICO frames including 8-bit and 32-bit compatibility images. The shared PNG reader now validates the zlib Adler-32 checksum as well as chunk CRCs. Arbitrary official-Installer artwork customization remains unverified and is not offered.
- Capture now stops for review and requires the official Launcher Generator and Installer. The desktop build path no longer downloads/substitutes the development toolchain or InstallScope installer. It shows executable/argument/working-directory details, rejects unchanged launcher output, and requires explicit per-build consent for recognized custom NSIS entry points. Real current official-tool execution remains a release gate.
- Added a ten-screen project planning workflow with versioned save/reopen snapshots, explicit license declarations, component inventory, background path checks, source-linked findings and configuration previews. Saving never overwrites an existing snapshot. Opening another project or closing the regular app requires confirmation when answers are unsaved. This is a foundation, not a finished builder: archive import, official-tool execution and installable package/final validation-report export remain unconnected and are labeled accordingly.

### Developer SDK
- Added an independent MIT Rust `portable-builder-kit` crate with bounded metadata parsing, Windows filename/path checks, actionable preflight findings, DOS/PE signature checks and host-supplied SHA-256 build receipts. Includes a native preflight example and Windows/Linux contract CI. Runtime portability and real official-tool execution still require Windows release verification.
- Added a shell-free compiler supervisor with timeouts, cancellation and Windows Job Object cleanup of compiler descendants. Packaging now uses it for tool downloads and compiler execution. The packaging screen has an accessible Cancel build control; captured files are retained, incomplete output is not reported as a successful package, and failed NSIS builds report a bounded diagnostic tail with the full local log path.
- Added real-process lifecycle tests and a Windows package lifecycle smoke job covering official-source launcher compilation, the InstallScope installer, launch, folder relocation and Data-preserving upgrades. The official Installer frontend remains a separate verification gate.

### Fixed
- The portable installer accepts whole-argument quoting of /DESTINATION and /AUTOCLOSE switches from normal process APIs, so paths containing spaces are installed to the requested location.
- Portable installer generation handles an optional Other folder containing only empty subdirectories. Required application files remain mandatory.
- Portable package compilation now checks the external Launcher Generator and Installer exit codes, validates the requested AppID against package metadata before tool acquisition, and rejects stale, unrelated, ambiguous or structurally invalid installer output. Previous output selection used only a recent modification time.

## [0.1.0] - 2026-10-20

First public release on GitHub.

### Added
- **Autostart Gatekeeper page** (Utilities; part of the opt-in Gatekeeper shipped earlier as a command line): the review queue is now a full page instead of terminal output. It shows each new or changed startup entry with its command, where it starts, the Installer Decrapifier's verdict and reasons, and who added it — attributed to an install log only when the evidence supports it, otherwise stated as unknown. **Keep** leaves the entry exactly as it is and stops future scans asking about it; **Remove** confirms first, deletes the entry through the same backed-up path as the Startup page, and says where the backup is. The page states how many entries are waiting (also shown as a badge in the navigation), can run a scan itself, and keeps the entries already decided behind a *Show entries you already decided* toggle. Turning the Gatekeeper on is offered on the page and in Settings (Advanced), and turning it on there runs a first scan so the queue is not empty for no visible reason. Like the rest of the interface, every control explains itself as a hover tooltip, on the page's focus line, and to screen readers — including why *Scan now* is unavailable while the Gatekeeper is off or a scan is running. No detection, backup or confirmation behavior changed: scans still run only when asked, nothing is blocked while an installer runs, and nothing is removed without an explicit decision. Still open: a periodic digest, services and scheduled-task coverage, and any background watcher.
- **Browser extensions** (Tools page): every extension installed in the supported Chromium-based browsers (Chrome, Edge, Brave, Vivaldi, Chromium, Opera, Opera GX) and Firefox-based browsers (Firefox, LibreWolf, Waterfox, Floorp), grouped by browser and profile. An extension can be disabled safely and reversibly: its files are moved into InstallScope's data folder (nothing is deleted, the rest of the profile is untouched) and restored to exactly where they were, with one click each way after a confirmation.
- **App Rewind, early prototype (CLI only)**: rewind one program to a recorded state without touching the rest of the PC. `installscope rewind <log-id> --list` shows the program's recorded states; `--to <state> --dry-run` prints the full plan, and anything that cannot be restored is named — a partial rewind is never presented as complete. Running a rewind (with `--yes`) takes a backup of the current state first, so the rewind itself can be undone from Backups, and records the moment before the rewind as a new state. File contents come from a new content store (`rewind` folder in the data folder, contents kept once each under their SHA-256) fed by `rewind <log-id> --capture`; the registry is restored from the install log's recorded before-images by the same reviewed machinery that uninstalls. The store has a storage budget (Settings, 2 GiB by default): older file states are evicted first, but a program's before-state and its newest state are never evicted, and every eviction is listed by `--list`. Not yet included: a graphical interface, and automatic capture of file contents while monitoring (today, capture is explicit with `--capture`).
- **Installer Decrapifier** (Monitor page, reviewing a recorded installation; CLI `installscope components <log-id>`): every service, scheduled task, autorun and Startup shortcut the installation added is listed and judged *Required for the program*, *Optional* or *Bloatware / telemetry / silent updater*, with the reasons. Bloat is ticked to be struck: it is removed (backed up first, unless backups are off in Settings) when the log is saved, and taken out of the log. Judging uses built-in rules; for components they can't judge, a language model running on this PC can be asked (Settings > Installer Decrapifier, any OpenAI-compatible endpoint such as Ollama). Only addresses on this computer are accepted, so nothing leaves it.
- **Background monitoring waits on Windows' registry change notifications** instead of checking every 30 seconds: between changes it uses no processor time at all, apart from the five-minute resource-use sample.
- **Faster, leaner snapshots**: paths and data are kept in shared pools instead of one allocation per entry, folders are listed with Windows' bulk directory reads, the registry is read with reused buffers, and two snapshots are compared in a single pass. Snapshots are saved in a compact binary format, written atomically and checked when loaded; snapshots saved by earlier versions still open.
- **Crash-safe removals**: every change is recorded in its backup, flushed to disk and written atomically, before it is made. A removal cut off by a crash or power loss is reported on the dashboard and the Backups page the next time InstallScope starts, with *Undo what was done* or *Keep as it is*; `installscope backups` marks it as interrupted.
- **Stronger protection of critical locations**: paths are compared the way Windows resolves them (`..`, trailing dots and spaces, `\\?\` prefixes, forward slashes), and where a folder really leads (junctions, symbolic links, short names) is checked before it is deleted with its contents; links are removed on their own, never their targets. More folders (everything directly inside Windows, System32 and SysWOW64, every user profile, Windows' folders at the top of the drive) and keys (SAM, SECURITY, HARDWARE, BCD, numbered control sets, Winlogon, IFEO, Policies, per-user class hives) are protected, and the registry layer itself refuses to delete them.
- **Stress tests**: very deep and wide registry trees, thousands of files, paths over 260 characters, links inside removed folders and files held open by another program.
- A note about Windows SmartScreen and checksums in the download instructions.
- **Release workflow, ready for signing and scanning**: when the repository has a code-signing certificate (`CODESIGN_PFX`, `CODESIGN_PASSWORD`), `InstallScope.exe` for x64 and Arm64 and the installer are signed and timestamped, with checksums computed afterwards; when it has a VirusTotal key (`VIRUSTOTAL_API_KEY`), every download is scanned before publishing and the release notes link each report. Both steps are skipped until the secrets are set.
- The performance check now also keeps `InstallScope.exe` under 40 MB.
- **Who is holding a locked file**: when a file can't be deleted because it is open, the removal says which program, service or Windows component has it (Windows Restart Manager), instead of only that it will go at the next restart.
- **Restart Windows Explorer during a removal** (Settings > Safety, on by default; CLI `revert --restart-explorer`): if Explorer has the program's shell extensions loaded, it is closed for the removal and started again afterwards, so those DLLs are deleted at once. Only Explorer is ever closed, never another program.
- **Close the program if it is running** (Settings > Safety, on by default; CLI `revert --close-programs`): running copies of the program being removed are asked to close, so they can save their work, and its files are then deleted at once. Only processes whose own program file is being removed are closed; an application that merely loaded one of its files (an add-in) is left running.
- **Try it, then undo** (Monitor page, where Windows Sandbox isn't available, such as Windows 11 Home): installs on this PC under monitoring after attempting a restore point, shows the full review, then removes everything the installation added, without Simple mode's trimming since every item came from that installer minutes earlier. *Keep it installed* saves an ordinary install log instead.
- **Locked-file tests on Windows**: a file open in another program, a DLL loaded by another process, a running program inside the folder being removed, an add-in host that must not be closed, and a real service that holds its files until its process has exited.
- **More installer types in the integration tests**: Squirrel (Atom) and a WiX Burn bundle (PowerToys), plus InstallShield and Wise once the `INSTALLSHIELD_URL` / `WISE_URL` repository variables point to a test installer.
- **Soak test**: `scripts/soak.ps1` installs and removes real programs in a loop with background monitoring running, failing on leftovers, background-monitoring misfires and growing handle or memory use; it runs for five hours weekly in CI and can run for days on a test VM.
- **Shared-component reference counting**: every removal review now cross-checks each item against all your install logs. Items are badged *Used only by this program*, *Shared with N other programs* (when another program's log also recorded the file, key, value, service or task) or *No install log mentions this*. Shared and unlogged items are never ticked automatically — including by *Select all* — and the review shows how many of your programs the reference data covers. The check is fully local; the CLI `revert` command prints the same labels.
- **Slowdown Detective history capture** (CLI `installscope history` and `installscope slowdown`): InstallScope now keeps a durable, versioned record of the changes behind "why is my PC slower than it was?" — programs installed, updated (with the version change) or removed, and autostart entries added, removed or changed — derived from install logs and from diffs of the installed-program and startup lists, stored as `history.json` in the data folder. `installscope slowdown --from YYYY-MM-DD --to YYYY-MM-DD` reports the period's changes, ranked by measured startup impact where Windows boot diagnostics or the usage tracker have a figure, and says so plainly when they don't. History starts accumulating from first use; early reports show an honest "not enough history yet" instead of invented numbers.
- **Autostart Gatekeeper** (opt-in; CLI `installscope gatekeeper`): when turned on (`installscope gatekeeper enable`, or Settings), each detection pass compares the programs that start with Windows — Run/RunOnce values and Startup-folder shortcuts — against a saved baseline. New or changed entries land in a review queue, attributed to the install log that added them when the evidence supports it (an entry recorded in a log is labeled with that program and the evidence; otherwise *unknown origin* — attribution is never guessed) and judged by the Installer Decrapifier rules. `installscope gatekeeper scan` runs one pass, `allow <id>` keeps an entry, `remove <id>` deletes it backed up first, exactly like other removals. The Gatekeeper never blocks an installer while it runs and never removes anything without your decision; undecided entries stay in the queue and out of the baseline.
- **Per-command CLI help**: `installscope <command> --help` (or `installscope help <command>`) prints that command's usage, flags, what it changes — including its backup and undo story — and how it confirms before destructive actions, then exits without doing anything. (Until now `--help` after a command was mistaken for an argument: `installscope revert --help` tried to load a log called "--help".) Errors for missing arguments now show the command's usage line instead of just naming the missing piece.

- Install monitoring: before/after snapshots of the registry and file system, run an installer under monitoring, or monitor manually; sessions survive restarts.
- Review captured changes, remove noise, and save them as an install log with auto-detected name, publisher and version.

### Changed
- Rebranded the project from Expunge to InstallScope and renamed the executable and CLI command. **Breaking change:** the installed data folder is now `%LOCALAPPDATA%\InstallScope`, the portable data folder is `InstallScopeData`, Task Scheduler tasks live under `InstallScope\…`, the uninstall registry key is `Software\Microsoft\Windows\CurrentVersion\Uninstall\InstallScope`, the context-menu verb is `InstallScopeInstall`, and program-transfer packages use the `.installscope` extension. Data created by Expunge-branded builds is not carried over.
- Thirteen fewer third-party libraries: dates and times (with Windows' own daylight-saving rules), SHA-256, byte search, folder walking, file-change watching, registry access, JSON reading and writing, compression (DEFLATE and gzip), ZIP archives, PNG images, the Open/Save/folder dialogs (Windows' own, called directly) and test folders are now InstallScope's own code, straight on the Windows API. Install logs, settings, backups and transfer packages are written byte for byte as before, and files from earlier versions open unchanged (checked against saved copies of the previous output). Snapshots and transfer packages are still standard gzip and ZIP files (checked against other programs' readers and writers); every ZIP entry's size and checksum is verified as it is read, and entry names that could escape the destination folder are refused.
- Live activity during monitoring waits on Windows' change notifications (`ReadDirectoryChangesW`, registry notifications) and wakes the moment monitoring ends, instead of checking a flag several times a second.
- A System Restore point is now created before uninstalling by default (Settings > Safety; it was off before). Settings files that already record the choice keep it — the new default only applies where the choice was never saved.
- **The command line asks before it destroys.** `revert`, `uninstall`, `clean`, `components --strike`, `restore`, `transfer import`, `gatekeeper remove`, `restore-point delete`, `restore-point rollback` and `rewind --to` now share one confirmation discipline, extending the `--yes` convention `rewind` and `rollback` started: in a terminal they describe what will happen — the targets, whether a backup is taken, what cannot be undone — and wait for a typed "yes"; without a terminal (scripts) they change nothing, refuse and exit 1 unless `--yes` is given. Read-only commands and `--dry-run` previews never ask; `clean --scheduled` (the Task Scheduler entry point) never asks, because the schedule is the standing instruction. **Scripted uses of these commands must add `--yes`** (the README's pipeline example now does). Relatedly, the "not running as Administrator" warning no longer fires for read-only commands, where it only trained users to ignore it.

- The project moved to **github.com/SeanShaffer88/InstallScope** (formerly InstallScopeUninstaller); old links redirect.
- The README now describes every tool in its own section.
- **Windows 11 only.** InstallScope is engineered for Windows 11 (build 22000 or later): on older Windows the app and the installer explain this and stop, instead of running with rules meant for Windows 11.
- Darker red accent (#6B0700) across the interface and window border; red text uses a lighter shade of it for readability.
- "Administrator" is capitalized throughout.
- New icon in #6B0700: dark card with a red E at large sizes, and an inverted red card with a black E at taskbar sizes (16–48 px), for the window and sidebar.
- Backups also export registry entries as a double-clickable `.reg` file; optional Recycle Bin.

### Removed
- The sidebar no longer shows four disabled “Planned” entries (Setup Package Creator, Developer Sandbox, Temporary Scratch Disk and VSS Viewer). They advertised features that do not exist yet; those features stay on the roadmap and will appear in the sidebar when they are real and working.

- InstallScope now focuses on being a complete, free replacement for Total Uninstall. Tools outside that scope were removed: the Anti-Telemetry page, the disk space map, the duplicate file finder, the Windows Updates remover, winget updates, the system health panel, the online reputation check, installer lint and the uninstaller test, repackaging and MSIX output, uninstall scripts, the Windows features and app aliases views, and Find by window.

### Fixed
- **Help and hover text no longer promises a backup unconditionally.** The page help for Programs, Backups, Bloatware Shield and the right-click menu, the first-run introduction, the Ask and Monitor review notes, the Backups page's empty state, the Startup and right-click menu notes and several hover texts all said removals are "backed up" without mentioning that Advanced mode can turn backups off, when no backup is taken. They now state the condition; the Recycle Bin setting's hover no longer claims "everything is backed up either way" (it appears on the same screen as the backups-off warning); the *Try it, then undo* hover says a restore point is attempted first rather than guaranteed (it is a best-effort extra — System Protection may be off); and the Installer Decrapifier entry above is corrected the same way. Text that was already conditional on the real setting, or that is only shown when a backup exists, is unchanged.
- **Dashboard "Space-wasters you don't use" no longer guesses when a program was last opened.** The panel ranked programs by size using "days not opened", but for programs Windows has no last-opened record for, that number was really days since installation — so a program installed over six months ago could be listed as "not opened for 6 months", and offered for uninstall, even if it was opened yesterday. The panel now lists only programs with a recorded last-opened date under that heading; when no program has one, the same list is shown for what it is — "Big programs installed long ago", with a note that their last-opened dates are unknown and they may still be in use. Programs left out for either reason are counted in a note under the panel (with a pointer to the Programs page) instead of vanishing silently, as are old programs whose size isn't known.
- **Control explanations are now reachable without a mouse (System Restore page first).** egui shows tooltips only while the mouse hovers, so keyboard, touch and screen-reader users could not reach them at all — and the System Restore page had none. Controls now carry their explanation three ways at once: as the hover tooltip (including while disabled, with the reason), as a line at the top of the page that follows keyboard focus, and as the description screen readers announce for the control. The System Restore page is covered completely — every button, the disk-space slider and the description field; the remaining pages follow in later phases of the same work. Information a user must have (such as needing administrator rights, or System Protection being off) stays in always-visible text, as before.
- **Removal text no longer claims a backup that does not exist.** The removal window's progress line always said "everything is backed up first", and the review said nothing at all — even with backups turned off in Advanced mode, when no backup is taken. The review now states the run's real safety net up front (a warning banner when backups are off), the progress line follows the run's own configuration, the "files created later" option no longer claims those files "are still backed up" when they are not, and the completion summary says plainly when no backup was taken, when a backup could not be completed, or when none was needed — naming the backup that can undo the removal when one exists, and the restore point the uninstall wizard created (and that it cannot bring back deleted files) when it is the only rollback. The uninstall wizard's confirmation says the same about its leftover removal instead of always promising a backup.
- **Bloatware Shield: deprovisioning no longer bypasses review.** Deprovisioning (removing the copies Windows keeps for new user accounts) used to start the moment removal was clicked, before the uninstall review even opened, so cancelling couldn't stop it — and nothing explained that it affects the whole PC and cannot be undone. Now the option states those risks on the page; choosing it always asks for a dedicated confirmation first (even when confirmations are turned off in Advanced mode); and the deprovisioning itself runs only after the app was actually removed — programs that were skipped or failed to uninstall keep their provisioned copies. The outcome of each run (what was deprovisioned, what failed) is saved and shown on the Bloatware Shield page until the next run.
- Background monitoring no longer holds gigabytes of memory: its snapshots and comparisons run in a short-lived copy of InstallScope, so the process that stays running for days stays small. Found by the new soak test, where it had grown from 17 MB to over 2 GB.
- Background monitoring could record its own duplicate log of an installation being monitored from the command line; `installscope monitor` now marks the installation as monitored (and refuses to start while another monitoring session is in progress).
- Removing an installation no longer fails trying to restore keys Windows keeps only in memory (such as WMI's), which Windows recreates itself; WMI runtime keys, Windows Search bookkeeping and text-input statistics are now treated as background noise.
- Removing a service no longer races its own files: InstallScope waits until the service has stopped and its process has exited (up to 30 seconds) before deleting the files it used, which were otherwise often left for the next restart.
- Waiting for an installer or for registry changes could loop forever if Windows reported the wait itself failed; such failures are now reported. Kernel handles are always closed, the running-process list is no longer cut off at 4,096 processes, and the System Restore library is released after use.
- **Map of where an installation put things** (Install logs, Monitor and Snapshots: *Map*): changes are grouped by what they mean (starts with Windows, services and drivers, scheduled tasks, Explorer and file types, Windows folders, program folders, AppData, ProgramData, shortcuts, your folders, temporary files, registry) with a proportional overview bar, area filters, search, and folders and keys that expand like a tree. *List* keeps the classic table.
- **Confidence colours on leftovers**: every item in a removal review is green (safe), yellow (review) or red (careful), with the reasons on hover; *Select only green* ticks just the certain ones.
- The uninstall wizard now says, before you start, that a program's own uninstaller cannot be undone by InstallScope (only the leftover removal afterwards is backed up), explains what a restore point does, and says why the restore-point option is unavailable when InstallScope isn't running as administrator — instead of silently greying it out.
- **Junk Cleaner shows its work before deleting**: a scan now keeps the full file list, each category has a *Review files* expansion listing exactly what would be deleted, and the Clean confirmation names every category it will clean with its size and file count plus the total. Cleaning deletes exactly the reviewed files — never a fresh scan behind your back — and a ticked category that was never scanned is named as not included instead of being cleaned unseen. A new **Protected paths** list on the Cleaner page (paths, folders or glob patterns, one per line) keeps files out of every clean: protected files a scan finds are listed as kept, never silently dropped, and the protection applies to `installscope clean` and scheduled cleans too. (The Recycle Bin still can't be listed or protected item by item — Windows reports it only as totals, and the page now says so.)
- **Monitor Review no longer claims a backup that may not happen, and Discard asks first**: the note under the Installer Decrapifier checklist said ticked background components are removed "backed up first" when the log is saved — but saving honors the Backups setting, so with backups off nothing was backed up and the strike could not be undone. The note now follows the setting in force: with backups on it names the Backups page as the undo path; with backups off it warns plainly, before anything is removed, that the strike will not be backed up and cannot be undone. Separately, the review's *Discard* button used to delete the only record of what an install changed with no confirmation at all; it now asks first, stating that the log and the saved "before" snapshot will be deleted, that the program stays installed, and that without the log the install can no longer be removed precisely or undone from it.
- **Pre-install check** (Monitor page): before an installer runs, InstallScope checks it for bundled adware (OpenCandy, InstallCore and others), offer screens, coin miners, web installers that download more while they run, missing or broken signatures and download-site wrappers.
- **Test in Windows Sandbox first** (Monitor page, Windows 11 Pro, Enterprise and Education): runs an installer in a throwaway copy of Windows and shows everything it changed, without touching the PC.

- **PortableApps Forge** (Tools > PortableApps Forge; CLI `installscope portable-build`): turns a program's installer into a PortableApps.com Format package. InstallScope snapshots Windows, watches for 30 seconds to learn background noise, runs the installer (silently for MSI, NSIS and Inno Setup when asked), lets you start the program once so its first-run settings are captured, snapshots again and builds the package from the difference: the program's files in `App\AppName`, `appinfo.ini`, icons taken from the program, `help.html`, the Launcher settings (`[RegistryKeys]`, `[DirectoriesMove]`, `[FilesMove]` and clean-ups, with paths written as Launcher variables) and, optionally, the first-run settings as `DefaultData`. The capture runs in **Windows Sandbox** when it is turned on, so the PC is never touched; otherwise it runs on this PC and is recorded as an install log so the program can be removed precisely afterwards. InstallScope compiles the launcher itself with the official PortableApps.com Launcher source and its NSIS compiler (included in release downloads, otherwise downloaded once from GitHub and checked against a pinned SHA-256), and builds the `.paf.exe` with its own installer script, which supports the PortableApps.com Platform's `/DESTINATION=` option, silent installs and keeps `Data` on upgrades; the official PortableApps.com Installer is used instead when it is installed. A **portability check** reports what could stop the program from working portably (Java, .NET runtimes, Visual C++ runtimes, services, drivers, shell extensions, administrator rights, 64-bit only), marks the package's dependencies (`UsesJava`, `Requires64bitOS`, `RequiresAdmin`, `[Activate] Java=require`) and copies Visual C++ runtime DLLs next to the program.
