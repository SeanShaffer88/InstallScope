# Changelog

## Unreleased

- Failures are no longer styled like ordinary status messages: errors show with a ✖ in the error colour, and error messages say what could not be done.

## 1.0.0.0 — local release package

- Six-card 3×2 board with passive System And OS information and top-right tool return buttons.
- Dedicated console entry point for retained diagnostics, dependency bundles, reviewed build execution and guarded environment apply/undo.
- Completed ten owned-interface catalogs: tooltips, safety/consent guidance, navigation and status templates; original evidence/commands/vendor reviews stay unchanged. Added exact placeholder/invariant audits and isolated compact-layout checks. Fixed long section-heading wrapping and report-preview growth.

- Five compact developer tools with dedicated instrument marks, task-specific windows and singleton behavior.
- Opening a tool hides the board; every tool can show it again without closing other windows. Closing the last tool restores it. Main header names the Windows Software Development Toolkit and keeps Settings at the far right.
- Integrated dependencies: .NET/CMake presets for x64/ARM64, official HTTPS downloads, pinned integrity and publisher checks, offline bundles, reviewed interactive installation and receipts.
- Native MSVC/Windows SDK/CMake/Ninja component selection and vendor-managed offline layout review, separate from pinned bundles.
- Bounded desktop project declarations and a review checklist linked to dependencies and build/test preparation.
- Explicit reviewed build/test execution with bounded logs, timeout/cancellation, contained child lifetime and saved-log triage handoff.
- Reviewed diagnostic export, project/log evidence handoff and conflict-checked environment recovery.
- Portable packaging with upstream notices, Cargo dependency inventory and checksums.
- See docs/RELEASE-VALIDATION.md for actual checks and environment limits.

- Independently reviewed all ten UI catalogs; corrected 80 semantic/terminology issues. Added a PowerShell 5.1 portable clean-host test harness with executable integrity checks, per-process environment isolation and explicit clean-OS limits.
